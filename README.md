## 5. Судлан шинжлэх тестийн аргачлал

Тестийн хамрах хүрээ, зорилго болон анхаарах чиглэлүүдийг `charter.md` файлд тодорхойлсон. Тестийн явцад системийн хэвийн ажиллагааг шалгахаас гадна буруу, хоосон болон хүлээгдээгүй өгөгдөл оруулах замаар алдаа илрүүлэхийг зорив.

Тестийн ажиглалт, хийсэн үйлдэл болон цагийн тэмдэглэгээг `session-notes.txt` файлд тэмдэглэсэн.

### 5.1. Тестийн үндсэн чиглэлүүд

**Оролтын өгөгдлийн баталгаажуулалт**

- Номын нэр, зохиогч болон хэвлэгдсэн оныг хоосон үлдээх
- Хэвлэгдсэн оны оронд тоон бус тэмдэгт оруулах
- Сөрөг тоон утга оруулах
- Систем буруу өгөгдлийг хүлээн авч байгаа эсэхийг шалгах

**Жагсаалт болон хайлтын ажиллагаа**

- Номын жагсаалтыг харах
- Хайлтаар тохирох болон тохирохгүй үр дүн хайх
- Шүүлтүүрийг өөрчилсний дараах жагсаалтын төлөвийг шалгах
- Жагсаалтын мэдээлэл болон нэгтгэсэн үзүүлэлтүүдийн нийцлийг ажиглах

**Устгах ажиллагаа**

- Ном устгах үйлдлийг гүйцэтгэх
- Устгасан ном жагсаалтаас хасагдсан эсэхийг шалгах
- Хэрэглэгчид харуулсан мэдэгдэл тухайн үйлдэлтэй нийцэж байгаа эсэхийг шалгах

**API-ийн алдаа боловсруулах ажиллагаа**

- REST API руу алдаатай JSON хүсэлт илгээх
- HTTP статус код болон буцаасан хариуг шалгах
- Хүсэлт амжилтгүй болсон нөхцөлд систем амжилттай гэсэн хариу өгч байгаа эсэхийг шалгах

### 6.1. BUG-01 — Хоосон мэдээлэлтэй ном нэмэгдэх

Ном нэмэх хэсгийн талбаруудыг хоосон үлдээн илгээхэд систем ном амжилттай нэмэгдсэн тухай мэдэгдэл харуулж, хоосон мэдээлэлтэй бичлэгийг жагсаалтад оруулсан.

**Хүлээгдэж буй үр дүн:** Шаардлагатай талбарууд хоосон үед систем ном нэмэх үйлдлийг хориглож, хэрэглэгчид алдааны мэдэгдэл харуулах ёстой.

**Боломжит нөлөө:** Хоосон болон утгагүй бичлэгүүд өгөгдлийн санд бүртгэгдсэнээр жагсаалтын чанар, статистик мэдээллийн үнэн зөв байдалд нөлөөлж болзошгүй.

Нотлох баримт: `screenshots/empty-books.png`

### 6.2. BUG-02 — Хэвлэгдсэн оны буруу утга хүлээн авах

Хэвлэгдсэн оны талбарт `abc` болон `-1` зэрэг утга оруулахад систем эдгээрийг зөвшөөрсөн. Тоон бус утга оруулсан үед дэлгэц дээр `NaN` утга харагдсан бол сөрөг утга оруулсан үед `-1` гэж харуулсан.

**Хүлээгдэж буй үр дүн:** Хэвлэгдсэн он нь зөвшөөрөгдсөн хүрээнд байгаа бүхэл тоо байх ёстой. Буруу утга оруулсан тохиолдолд систем үйлдлийг хориглож, хэрэглэгчид тайлбарласан алдааны мэдэгдэл өгөх шаардлагатай.

**Боломжит нөлөө:** Хүчин төгөлдөр бус өгөгдөл бүртгэгдэж, номын мэдээллийг харуулах болон боловсруулах үед алдаа үүсгэж болзошгүй.

Нотлох баримт: `screenshots/incorrect-values.png`

### 6.3. BUG-03 — Алдаатай JSON хүсэлт амжилттай гэсэн хариу авах

API-ийн алдаа боловсруулах ажиллагааг шалгахдаа бүрэн бус JSON агуулсан POST хүсэлт илгээсэн.

Туршилтад ашигласан команд:

```bash
curl -i -X POST http://localhost:3000/api/books \
  -H 'Content-Type: application/json' \
  --data '{"title":"Malformed Test","author":'
```

Хүсэлтэд JSON өгөгдөл дутуу байсан боловч систем дараах хариуг буцаасан:

```http
HTTP/1.1 200 OK
Content-Type: application/json

{"result":"OK"}
```

**Хүлээгдэж буй үр дүн:** Систем хүсэлтийн өгөгдөл буруу байгааг илрүүлж, тохирох алдааны HTTP статус код болон тайлбарласан хариу буцаах ёстой.

**Боломжит нөлөө:** Клиент програм хүсэлт амжилттай болсон гэж буруу ойлгож, API-ийн төлөв болон өгөгдлийн бүрэн бүтэн байдлын талаар буруу дүгнэлт гаргаж болзошгүй.

Нотлох баримт: `evidence/malformed-json-response.txt`

### 6.4. BUG-04 — Ном устгасны дараах буруу мэдэгдэл

Ном устгах үйлдлийн дараа систем устгалтыг илэрхийлэхийн оронд ном нэмэгдсэн тухай мэдэгдэл харуулсан.

**Хүлээгдэж буй үр дүн:** Ном амжилттай устгагдсан үед хэрэглэгчид устгалт амжилттай болсныг зөв илэрхийлсэн мэдэгдэл харуулах ёстой.

**Боломжит нөлөө:** Хэрэглэгч үйлдлийн үр дүнг буруу ойлгож, системийн ажиллагаанд эргэлзэхэд хүргэж болзошгүй.

Нотлох баримт: `screenshots/delete-success.png`

## 8. Тестийн үр дүнгийн дүгнэлт

Судлан шинжлэх тестийн явцад оролтын өгөгдлийг баталгаажуулах, API-ийн алдаатай хүсэлт боловсруулах болон хэрэглэгчид харуулах мэдэгдлийн зөв байдалтай холбоотой асуудлууд илэрсэн.

Гол ажиглалтууд:

- Хоосон мэдээлэлтэй ном нэмэх үйлдлийг систем хориглоогүй.
- Хэвлэгдсэн оны талбарт хүчин төгөлдөр бус утгууд оруулах боломжтой байсан.
- Алдаатай JSON хүсэлтэд амжилттай гэсэн HTTP хариу буцсан.
- Ном устгах үйлдлийн дараа үйлдэлтэй нийцэхгүй мэдэгдэл харуулсан.

Эдгээр үр дүнгээс үзэхэд системд оролтын өгөгдлийг шалгах дүрэм, API-ийн алдаа боловсруулах механизм болон үйлдэл тус бүрд тохирсон хэрэглэгчийн мэдэгдлийг сайжруулах шаардлагатай байна.

## 9. Сайжруулах санал

1. **Оролтын баталгаажуулалт:** Номын нэр, зохиогч болон хэвлэгдсэн оны талбаруудад сервер талын баталгаажуулалт хэрэгжүүлэх.
2. **Хэвлэгдсэн оны шалгалт:** Тоон бус утга, сөрөг тоо болон зөвшөөрөгдөөгүй хүрээний утгыг хүлээн авахаас татгалзах.
3. **API-ийн алдаа боловсруулах ажиллагаа:** JSON өгөгдлийг зөв эсэхийг шалгаж, буруу хүсэлтэд тохирох HTTP статус код болон тайлбарласан хариу буцаах.
4. **Хэрэглэгчийн мэдэгдэл:** Ном нэмэх, устгах болон бусад үйлдэлд тохирсон мэдэгдлүүдийг тус тусад нь харуулах.
5. **Өгөгдлийн нийцэл:** Номын жагсаалт, хайлтын үр дүн болон нэгтгэсэн статистик мэдээлэл хоорондоо нийцэж байгаа эсэхийг нэмэлтээр шалгах.
