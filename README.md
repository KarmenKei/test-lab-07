## 1. Төслийн танилцуулга

Энэхүү лабораторийн ажлын хүрээнд **«Уншлагын жагсаалт» v2.0** веб аппад судлан шинжлэх туршилт хийж, илэрсэн алдааг баримтжуулав.

Судлан шинжлэх тестийн зорилго нь урьдчилан тогтоосон тестийн тохиолдлуудаар хязгаарлагдахгүйгээр системийн ажиллагааг туршиж, гэнэтийн нөхцөл байдалд хэрхэн хариу үйлдэл үзүүлж байгааг шалгах, илэрсэн алдааг дахин үүсгэх боломжтойгоор тэмдэглэж, холбогдох нотлох баримтыг бүрдүүлэхэд оршино.

Тестийн явцад дараах үндсэн чиглэлүүдэд анхаарсан. Үүнд:

- Ном нэмэх үеийн оролтын өгөгдлийн баталгаажуулалт
- Номын хэвлэгдсэн оны утгын шалгалт
- Номын жагсаалт болон хайлтын ажиллагаа
- Өгөгдлийн бүрэн бүтэн байдал, нэгтгэсэн мэдээллийн нийцэл
- Ном устгах ажиллагаа болон хэрэглэгчид харуулах мэдэгдэл
- REST API хүсэлтийн өгөгдөл шалгах, алдаатай хүсэлтэд хариу өгөх ажиллагаа

## 4. Системийг ажиллуулах заавар

### 4.1. Шаардлагатай орчин

- Төслийн репозиторыг локал компьютерт татсан байх

Терминал нээж төслийн хавтас руу шилжинэ.

node app.js

http://localhost:3000

## 5. Судлан шинжлэх тестийн аргачлал

Тестийн хамрах хүрээ, зорилго болон анхаарах чиглэлүүдийг `charter.md` файлд тодорхойлсон. Тестийн явцад системийн хэвийн ажиллагааг шалгахаас гадна буруу, хоосон болон хүлээгдээгүй өгөгдөл оруулах замаар алдаа илрүүлэхийг зорив.

Шинэ туршилтын ажиглалтыг [туршилтын тайланд](session-report.md) цагийн дарааллаар тэмдэглэсэн. Өмнөх туршилтын тэмдэглэл `session-notes.txt` файлд бий.

### 5.1. Тестийн үндсэн чиглэлүүд

**Оролтын өгөгдлийн баталгаажуулалт**

- Номын нэр, зохиогч болон хэвлэгдсэн оныг хоосон үлдээх
- Хэвлэгдсэн оны оронд тоон бус тэмдэгт оруулах
- Сөрөг тоон утга оруулах
- Систем буруу өгөгдлийг хүлээн авч байгаа эсэхийг шалгах

**Жагсаалт болон хайлтын ажиллагаа**

- Номын жагсаалтыг харах
- Хайлтаар тохирох болон тохирохгүй үр дүн хайх
- Шүүлтүүрийг өөрчилсний дараах жагсаалтын төлөвийг шалгах
- Жагсаалтын мэдээлэл болон нэгтгэсэн үзүүлэлтүүдийн нийцлийг ажиглах

**Устгах ажиллагаа**

- Ном устгах үйлдлийг гүйцэтгэх
- Устгасан ном жагсаалтаас хасагдсан эсэхийг шалгах
- Хэрэглэгчид харуулсан мэдэгдэл тухайн үйлдэлтэй нийцэж байгаа эсэхийг шалгах

**API-ийн алдаа боловсруулах ажиллагаа**

- REST API руу алдаатай JSON хүсэлт илгээх
- HTTP статус код болон буцаасан хариуг шалгах
- Хүсэлт амжилтгүй болсон нөхцөлд систем амжилттай гэсэн хариу өгч байгаа эсэхийг шалгах

### 6.1. BUG-01 — Хоосон мэдээлэлтэй ном нэмэгдэх

Ном нэмэх хэсгийн талбаруудыг хоосон үлдээн илгээхэд систем ном амжилттай нэмэгдсэн тухай мэдэгдэл харуулж, хоосон мэдээлэлтэй бичлэгийг жагсаалтад оруулсан.

**Хүлээгдэж буй үр дүн:** Шаардлагатай талбарууд хоосон үед систем ном нэмэх үйлдлийг хориглож, хэрэглэгчид алдааны мэдэгдэл харуулах ёстой.

**Боломжит нөлөө:** Хоосон болон утгагүй бичлэгүүд өгөгдлийн санд бүртгэгдсэнээр жагсаалтын чанар, статистик мэдээллийн үнэн зөв байдалд нөлөөлж болзошгүй.

Шинэ туршилтаар гарчиг болон зохиогчийн талбарыг тус тусад нь хоосон үлдээж шалгав. Апп хоёр тохиолдолд хоёуланд нь «Ном нэмэгдлээ» гэж мэдэгдэж, тухайн талбар нь хоосон мөр нэмсэн.

Нотлох баримт: [гарчиггүй мөр](screenshots/bug-01-missing-title.png), [зохиогчгүй мөр](screenshots/bug-01-missing-author.png), [өмнөх зураг](screenshots/empty-books.png).

### 6.2. BUG-02 — Хэвлэгдсэн оны буруу утга хүлээн авах

Хэвлэгдсэн онд `-1` оруулахад систем «Ном нэмэгдлээ» гэж мэдэгдэж, хүснэгтэд `-1` онтой «Year Test» мөр нэмсэн. Хязгаарын шалгалтаар `1000`, `2100` зөв нэмэгдсэн боловч `999`, `2101` онтой номыг мөн зөвшөөрсөн.

**Хүлээгдэж буй үр дүн:** Хэвлэгдсэн он нь зөвшөөрөгдсөн хүрээнд байгаа бүхэл тоо байх ёстой. Буруу утга оруулсан тохиолдолд систем үйлдлийг хориглож, хэрэглэгчид тайлбарласан алдааны мэдэгдэл өгөх шаардлагатай.

**Боломжит нөлөө:** Хүчин төгөлдөр бус өгөгдөл бүртгэгдэж, номын мэдээллийг харуулах болон боловсруулах үед алдаа үүсгэж болзошгүй.

Нотлох баримт: `screenshots/invalid-year.png`

### 6.3. BUG-03 — Алдаатай JSON хүсэлт амжилттай гэсэн хариу авах

API-ийн алдаа боловсруулах ажиллагааг шалгахдаа бүрэн бус JSON агуулсан POST хүсэлт илгээсэн.

Туршилтад ашигласан команд:

```bash
curl -i -X POST http://localhost:3000/api/books \
  -H 'Content-Type: application/json' \
  --data '{"title":"Malformed Test","author":'
```

Хүсэлтэд JSON өгөгдөл дутуу байсан боловч систем дараах хариуг буцаасан:

```http
HTTP/1.1 200 OK
Content-Type: application/json

{"result":"OK"}
```

**Хүлээгдэж буй үр дүн:** Систем хүсэлтийн өгөгдөл буруу байгааг илрүүлж, тохирох алдааны HTTP статус код болон тайлбарласан хариу буцаах ёстой.

**Боломжит нөлөө:** Клиент програм хүсэлт амжилттай болсон гэж буруу ойлгож, API-ийн төлөв болон өгөгдлийн бүрэн бүтэн байдлын талаар буруу дүгнэлт гаргаж болзошгүй.

Нотлох баримт: [шинэ туршилтын curl гаралт](evidence/bug-03-curl.txt).

### 6.4. BUG-04 — Ном устгасны дараах буруу мэдэгдэл

Ном устгах үйлдлийн дараа систем устгалтыг илэрхийлэхийн оронд ном нэмэгдсэн тухай мэдэгдэл харуулсан.

**Хүлээгдэж буй үр дүн:** Ном амжилттай устгагдсан үед хэрэглэгчид устгалт амжилттай болсныг зөв илэрхийлсэн мэдэгдэл харуулах ёстой.

**Боломжит нөлөө:** Хэрэглэгч үйлдлийн үр дүнг буруу ойлгож, системийн ажиллагаанд эргэлзэхэд хүргэж болзошгүй.

Нотлох баримт: [устгахаас өмнөх зураг](screenshots/bug-04-before-delete.png), [устгасны дараах зураг](screenshots/bug-04-after-delete.png).

| `session-notes.txt` | Өмнөх туршилтын тэмдэглэл |
| `bugs/` | Алдаа тус бүрийн дэлгэрэнгүй тайлан |

Нотлох баримт бүр тухайн алдааны тайлан дахь алхам, хүлээгдэж буй үр дүн болон бодит үр дүнг баталгаажуулахад ашиглагдана.

## 8. Тестийн үр дүнгийн дүгнэлт

Судлан шинжлэх тестийн явцад оролтын өгөгдлийг баталгаажуулах, API-ийн алдаатай хүсэлт боловсруулах болон хэрэглэгчид харуулах мэдэгдлийн зөв байдалтай холбоотой асуудлууд илэрсэн.

Гол ажиглалтууд:

- Хоосон мэдээлэлтэй ном нэмэх үйлдлийг систем хориглоогүй.
- Хэвлэгдсэн оны талбарт хүчин төгөлдөр бус утгууд оруулах боломжтой байсан.
- Алдаатай JSON хүсэлтэд амжилттай гэсэн HTTP хариу буцсан.
- Ном устгах үйлдлийн дараа үйлдэлтэй нийцэхгүй мэдэгдэл харуулсан.

Эдгээр үр дүнгээс үзэхэд системд оролтын өгөгдлийг шалгах дүрэм, API-ийн алдаа боловсруулах механизм болон үйлдэл тус бүрд тохирсон хэрэглэгчийн мэдэгдлийг сайжруулах шаардлагатай байна.

## 9. Сайжруулах санал

1. **Оролтын баталгаажуулалт:** Номын нэр, зохиогч болон хэвлэгдсэн оны талбаруудад сервер талын баталгаажуулалт хэрэгжүүлэх.
2. **Хэвлэгдсэн оны шалгалт:** Тоон бус утга, сөрөг тоо болон зөвшөөрөгдөөгүй хүрээний утгыг хүлээн авахаас татгалзах.
3. **API-ийн алдаа боловсруулах ажиллагаа:** JSON өгөгдлийг зөв эсэхийг шалгаж, буруу хүсэлтэд тохирох HTTP статус код болон тайлбарласан хариу буцаах.
4. **Хэрэглэгчийн мэдэгдэл:** Ном нэмэх, устгах болон бусад үйлдэлд тохирсон мэдэгдлүүдийг тус тусад нь харуулах.
5. **Өгөгдлийн нийцэл:** Номын жагсаалт, хайлтын үр дүн болон нэгтгэсэн статистик мэдээлэл хоорондоо нийцэж байгаа эсэхийг нэмэлтээр шалгах.

## 10. Хязгаарлалт

Энэхүү тайлан нь баримтжуулсан судлан шинжлэх тестийн ажиглалт болон хадгалсан нотлох баримтад тулгуурласан болно. Тестийн явцад шалгагдаагүй функц, орчин болон нөхцөл байдлын талаар бүрэн дүгнэлт хийх боломжгүй.

Илэрсэн алдаа бүрийн бодит нөлөө, дахин үүсэх нөхцөл болон засварын дараах үр дүнг нэмэлт тестээр баталгаажуулах шаардлагатай.

## 11. Дүгнэлт

Энэхүү лабораторийн ажлаар «Уншлагын жагсаалт» v2.0 веб аппын үндсэн ажиллагааг шалгаж, алдаа бүрийн дахин гаргах алхам, хүлээгдсэн болон бодит үр дүнг нотлох баримтын хамт тэмдэглэв.

Тестийн үр дүн нь системийн найдвартай ажиллагааг сайжруулахад оролтын баталгаажуулалт, API-ийн алдаа боловсруулах ажиллагаа болон хэрэглэгчийн интерфейсийн мэдэгдлийг зөв зохион байгуулах нь чухал болохыг харуулж байна.

## Хэсэг E — Туршилтын дүгнэлт

Supermodel аяллаар хамгийн олон доголдол илэрсэн бөгөөд устгалын мэдэгдэл, урт гарчгаас үүдсэн хүснэгтийн байрлал, «Хуучин хувилбар» холбоос, оны харагдах хэлбэр, устгах товчны өнгийг баримтжуулав (BUG-04, BUG-07, BUG-09, BUG-10, BUG-11). Couch Potato аяллаар хоосон гарчиг, хоосон зохиогчтой ном бүртгэгдэж, зөвшөөрсөн хүрээнээс гадуурх он хүлээн авч байгааг тогтоов (BUG-01, BUG-02). Fed-Ex аяллаар тоолуурын зөрүү, том жижиг үсгээс хамаарсан хайлт, ижил номын давхар бүртгэлийг илрүүлж, зохиогчийн нэрийг ижил бичихэд хайлт амжилттай болдгийг шалгав (BUG-05, BUG-06, BUG-08). Saboteur аяллаар дутуу JSON-д HTTP 200 буцаж, зөв JSON-д HTTP 201 буцсаныг харьцуулан, хуучин хувилбарын холбоосын HTTP 500 хариуг баталгаажуулав (BUG-03, BUG-09).

Үндсэн үйлдлүүдийг шалгах явцад төлөвлөгөөнд тусгайлан дурдаагүй «Хуучин хувилбар» холбоосыг нээж, серверийн алдааг илрүүлэв. Туршилтын тэмдэглэлд бутархай он, гарын товчлуураар удирдах боломж болон бусад веб хөтөч дээрх ажиллагааны шалгалт бүртгэгдээгүй.

Playwright-аар талбарын баталгаажуулалт, давхардсан мөр, хайлтын үр дүн, жагсаалтын тоолуур, устгалын мэдэгдэл болон HTTP төлөвийг хүлээгдсэн утгатай тулган шалгаж болно. Хүснэгтийн байрлал, оны бичиглэл, устгах товчны өнгөний зөрүүг дэлгэцийг ажиглах явцад анзаарсан. Эдгээр харагдах байдлын доголдлыг давтан шалгахад Playwright-д цонхны хэмжээг тогтоож, харагдах талбай, бичвэр эсвэл товчны өнгийг тусад нь шалгах нөхцөл нэмж болно.
